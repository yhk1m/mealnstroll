# 급식먹고산책 3D 전환: 기술 구성 설계

작성일: 2026-11-15, 가지(branch): `3d`

## 0. 배경과 범위

급식먹고산책(mealnstroll.bgnl.kr)은 지금 Vite + 순수 JS + Canvas 2D + Supabase Realtime으로 동작한다. 이를 서울 양정고를 무대로 한 3D 산책 공간으로 바꾼다. 그림체, 코스, 날씨와 계절, 캐릭터는 이미 시안(비공개 Artifact, three 0.147)에서 확정했다.

3D 전환은 네 덩어리로 나눈다. **이 문서는 1과 2를 다룬다.**

1. 3D 세계: 학교, 나무, 하늘, 날씨, 계절, 캐릭터와 걷기
2. 다중 접속: 위치 동기화, 방 나누기, 산책 참여
3. 기존 기능 이식: 접어 둔 채팅, 서명 공지, 운세, 오래 머물기 효과 (1과 2 위에 얹는다, 별도 설계)
4. 미니게임 4종과 결과 공유 (별도 설계)

### 확정된 결정

| 항목 | 결정 |
|---|---|
| 전환 방식 | `3d` 가지에서 개발, Vercel 미리 보기 주소로 확인, 완성되면 main에 합쳐 같은 주소에서 한 번에 교체 |
| 대상 기기 | 교무실 PC와 휴대폰 반반. 느린 기기는 자동으로 가벼운 화면 |
| 방 배정 | 자동 배정(30명 단위) + 같이 걷기 링크 `#room=N` |
| 접속 기반 | Supabase Realtime 무료 요금제 유지. 움직임은 목적지만 보낸다 |
| 확장 | 인기가 생기면 그때 유료 또는 별도 서버 검토. 이를 위해 Supabase 의존을 `net/` 한 곳에 가둔다 |
| 신원 | 지금처럼 로그인 없음. 기기 고유 번호(`mealnstroll.id`)와 이름, 복장을 그 기기에 저장 |
| 화면 이름 | "급식먹고산책"만 쓴다 |

## 1. 전체 구조

three.js는 npm 패키지로 넣는다(시안의 CDN 방식 대신). 시안 코드가 0.147 API(`outputEncoding`, `sRGBEncoding`)를 쓰므로 `three@0.147.0`으로 고정하고, 판 올리기는 나중 일로 둔다. 개발 중 입구는 `walk3d.html`이고 2D `index.html`은 교체 때까지 그대로 둔다. 소스는 다음 묶음으로 나눈다. 각 묶음은 다른 묶음의 내부를 모른 채 공개 함수로만 쓴다.

| 묶음 | 하는 일 | 의존 |
|---|---|---|
| `src/world/` | 학교 건물(`yangchung-3d/campus-data.js`의 외부 좌표만 복사, OSM 출처 표기), 나무 5종과 관목(가지 생성, 숲과 불규칙 줄 배치), 하늘과 해 위치, 날씨, 계절, 크리스마스 | three |
| `src/avatar/` | 2.5등신 캐릭터, 교사 복장 8종, 발을 땅에 붙이는 걷기, 먼 거리용 단순 모양 | three |
| `src/data/` | 시안에서 뽑아낸 학교 자료(`campus.json`)와 코스 좌표(`courses.json`) | 없음 |
| `src/move/` | 걸을 수 있는 땅 격자, 길 찾기, 코스 4개, `positionAt(motion, t)` | 없음(순수 함수) |
| `src/net/` | 서버 시각 보정, 방 배정, 접속자 목록, 움직임 주고받기, 공지 채널 | Supabase(여기만) |
| `src/quality.js` | 화면 속도 측정, 고화질과 가벼운 화면 전환 | 없음 |
| `src/ui/` | 이름과 복장 고르기, 방 표시와 링크 복사, 걷는 속도, 시간대(지금, 낮, 노을, 밤), 연결 상태 | DOM |
| `src/main.js` | 위 묶음을 이어 붙이고 그리기 반복 실행 | 전부 |

- 도면 유래 내부(`interiors`)와 화장실 자료는 학생 안전을 위해 공개 빌드에 넣지 않는다.
- 2D 코드는 교체 시점에 지운다. git 기록에 남는다.
- 기존 `api/notice-sign.js`, `src/notice-auth.js`는 그대로 쓴다.

## 2. 움직임 기록과 위치 계산

각 접속자는 Supabase presence 상태에 다음을 싣는다.

```js
{
  name, outfit,            // 화면 표시
  joinedAt,                // 오래 머물기 단계 계산용, 서버 시각 기준(ms)
  motion                   // 아래 셋 중 하나
}

// 제자리
{ kind: 'idle', at: [x, z], face: rad }
// 바닥 클릭 이동
{ kind: 'go', pts: [[x, z], ...], speed: m_per_s, t0, then? }
// then: 도착하면 코스를 이어 걷는다 { course, offset } (산책 참여 버튼)
// 산책 참여
{ kind: 'course', course: 'track'|'campus'|'outside'|'road', speed: m_per_s, t0, offset: m }
```

- 좌표는 학교 기준 미터, 소수 첫째 자리까지 반올림해 보낸다.
- `t0`는 서버 시각 기준 ms다.
- `positionAt(motion, now)`는 위치와 바라보는 방향을 돌려주는 순수 함수다. `go`는 마지막 지점에 닿으면 그 자리에 서거나, `then`이 있으면 도착 시각을 `t0`로 삼아 코스를 걷는다. `course`는 코스 길이로 나머지 연산을 해 계속 돈다.
- 걷는 속도는 3단계(0.7, 1, 1.4m/s). 오래 머물기 효과의 속도 증가는 3번 설계에서 다시 정한다.

**바닥 클릭 처리**
1. 누른 지점을 걸을 수 있는 땅 격자(1m 칸, 건물 다각형과 학교 밖 금지 구역 표시)에서 가장 가까운 걸을 수 있는 칸으로 옮긴다.
2. 현재 위치에서 A*로 길을 찾고, 직선으로 이어지는 칸을 지워 꺾이는 지점만 남긴다(최대 32개).
3. `go` 기록을 만든다. 받는 쪽은 길을 다시 찾지 않는다.

**서버 시각 보정**
- 작은 Vercel 함수 `api/time.js`가 `Date.now()`를 돌려준다.
- 접속할 때 세 번 물어 왕복 시간이 가장 짧은 응답으로 차이를 정한다. 실패하면 차이 0으로 둔다.

## 3. 방 나누기와 채널

**채널**
- 방 채널 `mealnstroll-room-N` (N = 1~20): presence(접속자 목록과 움직임), 채팅 broadcast.
- 공지 채널 `mealnstroll-notice`: presence 없이 broadcast만. 서명 공지, 공지 지우기, 늦게 온 사람의 공지 요청.
- 지금의 `mealnstroll-lobby`는 교체 시점에 쓰지 않게 된다.

**배정 순서**
1. 링크에 `#room=N`이 있으면 N부터, 없으면 1부터 시도한다.
2. 채널에 들어가 첫 presence sync를 기다린다(최대 3초).
3. 나를 뺀 인원이 30명 이상이면 나와서 다음 번호로 간다. 링크로 왔다면 "N번 방이 가득 차서 M번 방으로 왔어요"를 띄운다.
4. 20번까지 모두 차면 20번 방에 그냥 들어간다.
5. 거의 동시에 들어와 31명이 되는 경우는 허용한다.

화면 구석에 "N번 방 K명"과 "같이 걷기 링크 복사" 버튼을 둔다.

**메시지 아끼기**
- 움직임은 presence `track` 한 번으로만 알린다(별도 broadcast 없음).
- 바닥 클릭은 0.5초에 한 번까지만 보낸다. 그 안에 다시 누르면 마지막 것만 0.5초 뒤에 보낸다.
- 서 있거나 코스를 도는 동안에는 보내지 않는다.

## 4. 오류 처리

| 상황 | 처리 |
|---|---|
| 연결 끊김 | 화면 유지, "다시 연결하는 중" 표시, 같은 방으로 재접속. 다른 사람 캐릭터는 마지막 기록대로 계속 움직이고, 30초 안에 돌아오면 사라지지 않게 한다 |
| Supabase 설정 없음, 연결 불가 | 혼자 걷는 모드 |
| 날씨 API 실패 | 맑음 |
| WebGL 없음 | "이 기기에서는 3D가 열리지 않아요" 안내 |
| 이상한 움직임 기록 | 좌표가 학교 영역 밖, 속도 0.3~3m/s 밖, 지점 33개 이상, 코스 이름 모름, 숫자가 아님 → 무시하고 그 사람을 마지막 정상 위치에 세운다 |
| 이름, 복장 이상 | 이름 12자 자르기, 모르는 복장은 기본 복장 |

## 5. 성능

- 목표: PC 50fps 이상, 휴대폰 30fps 이상.
- `quality.js`가 처음 3초의 평균 fps를 재서 목표보다 낮으면 가벼운 화면으로 바꾼다. 가벼운 화면은 그림자 끔, 나무 절반, `devicePixelRatio` 최대 1. 설정에서 직접 고를 수 있고 선택은 그 기기에 저장한다.
- 나무와 관목은 `InstancedMesh`로 그린다.
- 카메라에서 25m 넘게 떨어진 캐릭터는 단순 모양으로 바꾸고 걷기 동작은 2프레임에 한 번 갱신한다.
- 첫 화면 JS는 gzip 약 1MB 안쪽. 미니게임은 동적 `import()`로 나중에 불러온다.
- 탭이 가려지면(`visibilitychange`) 그리기를 멈춘다.
- `#fps`를 붙이면 화면 구석에 fps를 표시한다.

## 6. 확인 방법

**자동 테스트** (`npm test`, node --test)
- `positionAt`: idle, go(중간, 끝 지난 뒤), course(한 바퀴 넘김, offset)
- 길 찾기: 건물을 지나지 않는다, 막힌 곳을 누르면 가까운 칸으로 간다, 지점 수 32개 이하
- 방 고르기: 인원에 따라 다음 번호, 링크 번호 우선, 20번 상한
- 움직임 기록 검사: 4절의 이상 기록이 모두 걸러진다
- 시각 보정: 왕복이 가장 짧은 응답을 고른다

**직접 확인**
- 브라우저 창 여러 개를 같은 방에 띄워 위치가 일치하는지, 31번째 접속이 다음 방으로 가는지 본다(인원은 테스트용 숨은 설정으로 정원을 3명으로 낮춰 확인).
- 헤드리스 Chrome(`--disable-gpu`)으로 낮, 노을, 밤, 눈 오는 날 장면을 찍는다.
- 실제 휴대폰 1대와 교무실 PC 1대의 fps는 사용자가 `#fps`로 잰다.
